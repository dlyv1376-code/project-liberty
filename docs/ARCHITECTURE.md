PROJECT LIBERTY — Architecture Blueprint

Version: 0.1
Status: Draft — Research and Architecture

1. Mission

PROJECT LIBERTY is an independent, privacy-focused decentralized blockchain ecosystem.

Our goal is to build an open network where users control their data, developers can freely create applications, and anyone can operate an independent node without permission from a central organization.

The first planned flagship application is CryptoPhoto, designed to protect photographs using encryption and secure recovery mechanisms.

2. Core Principles

- Privacy by design.
- Open-source development.
- Permissionless application development.
- Independent network infrastructure.
- User control over cryptographic keys.
- Transparent protocol rules and tokenomics.
- Independent security reviews and audits.
- No dependence on a single founder or organization.

3. Blockchain Core

The current development strategy is to study and evaluate the Monero codebase as a potential foundation.

Research areas:

- Transaction and block validation.
- Peer-to-peer networking.
- Wallet architecture.
- Privacy mechanisms.
- Node operation.
- Consensus and network security.
- Build and testing infrastructure.

A fork does not automatically inherit the security guarantees of its upstream project.

All modifications must be tested and independently reviewed.

4. Consensus and Nodes

The consensus mechanism has not yet been selected.

Proof of Work and RandomX are research candidates, not final decisions.

Anyone should be able to operate an independent node without requiring permission.

Running a node and producing blocks are separate functions. Block production depends on the consensus rules.

5. Privacy and Cryptography

Financial transaction privacy and file encryption are separate security layers.

The project will prioritize:

- Established cryptographic algorithms.
- Client-side encryption.
- Secure key management.
- Threat modelling.
- Metadata protection.
- Independent security audits.

We do not promise absolute privacy or perfect security.

6. CryptoPhoto

CryptoPhoto is the first planned flagship application.

Its purpose is to protect photographs through encryption and carefully designed recovery options.

Research areas:

- Encryption before external storage.
- Secure key generation and management.
- Backup and recovery.
- Secure sharing.
- Metadata protection.
- User-friendly security controls.

Secret sharing, including a possible 2-of-3 recovery model, remains an option to evaluate, not a finalized decision.

7. Encrypted Storage

Large photographs and files should not be stored directly on the blockchain.

A separate encrypted storage layer will be researched.

It must consider:

- Data integrity.
- Availability.
- Replication.
- Metadata leakage.
- Storage costs.
- User access and recovery.

8. Developer Ecosystem

PROJECT LIBERTY aims to allow anyone to create and publish applications freely.

No founder permission, application registration fee, or listing fee should be required.

Users may pay ordinary network fees when performing operations that consume blockchain resources.

The application execution model, SDK, and APIs remain under research.

9. Development Technologies

Current strategic direction:

- C++ for the blockchain core.
- Rust may be considered for independent modules.
- Kotlin may be considered for Android applications.

These choices remain subject to technical evaluation.

10. Security and Governance

The project aims to establish:

- Public source code.
- Transparent development.
- Independent audits.
- Reproducible builds.
- Documented protocol changes.
- Responsible vulnerability disclosure.
- Community participation in governance.

11. Open Questions

The following decisions are not finalized:

- Consensus mechanism.
- Network parameters.
- Token supply and emission.
- Transaction fees.
- Storage architecture.
- Application execution model.
- Governance and upgrade procedures.
- Key recovery architecture.

12. Current Development Stage

PROJECT LIBERTY is currently in the research and architecture stage.

No production blockchain, token, or CryptoPhoto implementation is being claimed at this stage.

Our priority is to build correctly, transparently, and securely — step by step.
